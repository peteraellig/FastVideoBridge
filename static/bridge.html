SDI input and output

Install Blackmagic Desktop Video on this computer. SDI inputs appear in Input source; select a free connector and click Set source. Input follows detected resolution and frame rate. Embedded audio: channels 1 and 2 form the stereo pair unless Settings, Input audio selects another pair or one channel.

For WHIP or WHEP reception, choose Blackmagic SDI output on Main and select its connector. Received video uses the existing hardware decoder. SDI follows the received format and schedules video and audio on the same hardware timeline; with Interlaced output · 1080i, 1080 pictures leave as 1080i (see Output format → Interlaced sources on the sender). If a format is unsupported, select 720p output in Settings; frame rate still follows the source.

Connector profiles and physical routing remain in Blackmagic Desktop Video Setup. Bridge does not change them or take over occupied connectors. Use separate free connectors for simultaneous input and output. SDI needs no network media bandwidth after reception.

Connect two Bridge computers

For WHIP, open the receiver's port on the receiving computer. The sender uses that receiver's WHIP URL and stream key.

The port shown here is this computer's Settings → Receive port. If you send to another computer, use the port shown in its Settings.

I want to send with WHIP

  1. Ask the receiver for its WHIP URL and stream key.
  2. On Main, select your input and start it. Enter the URL and key in the WHIP container.
  3. Click Start WHIP.

Ports: Bridge connects to the port in the destination URL. Normally, no router port forwarding is needed at the sender. Allow Bridge in Windows Firewall using Sender below.

Your own Receive port is used only when someone sends to this computer.

I want to receive WHIP

  1. In Settings, choose Receive port (currently 56208) and click Save.
  2. For Internet reception, enter your public IPv4. In the receiver's router, forward TCP and UDP on that same port to this computer's LAN IP, using the same internal port. In the same LAN, skip this step.
  3. Apply the Windows Firewall rules below with role Receiver.
  4. On Main, choose WHIP input, enter a stream key, select OMT, NDI or SDI output and click Start receiver. Give the sender the WHIP URL and the same key.

Why both? TCP starts the connection. UDP carries the video and audio.

Example address: http://PUBLIC-IP:56208/api/whip-input. Internet reception needs a reachable public IPv4 on the receiver's connection.

I want to send with SRT

  1. Start an SRT listener on the receiving application.
  2. In Bridge's SRT container, enter the receiver's IP and listener port (currently 56201), then click Start SRT.

Ports: For Internet reception, the listener's router forwards UDP on the listener port to its computer. The listener's Windows Firewall must allow that port. Normally, the sending Bridge needs no router forwarding.

Bridge sends as caller. Its Receive port is a WHIP setting and does not set the SRT destination.

I want to receive a FastVideo link

  1. On Main, choose FastVideo link / WHEP.
  2. Paste the complete viewer link, select OMT, NDI or SDI output and click Connect.

Ports: No router forwarding is normally needed on this receiving computer. Bridge connects outwards, like a browser. Allow outgoing HTTPS and WebRTC UDP.

The FastVideo server handles its own Internet access. A personal link counts as one viewer connection.

Allow Bridge in Windows Firewall

Run once on each Bridge computer. Choose what this computer does, then confirm the Windows administrator prompt. Keep Windows Firewall enabled.

The button configures Windows Firewall only. Router forwarding is set in your router. For NDI output, select NDI on Main before applying Receiver or Both rules. To use the downloaded script on another PC: right-click → Run with PowerShell, then confirm.

Manual firewall setup and older receivers
  1. Press Windows + R, type wf.msc and open Inbound Rules → New Rule → Custom.
  2. Select the receiving Bridge's program, normally C:\FastVideoBridge\.runtime\python.exe.
  3. Allow TCP on the receiving port. Repeat for UDP on the same port.
  4. Choose the active Windows network profile. For a LAN-only rule, restrict remote addresses to Local subnet.

If outgoing connections are blocked by your organisation, its administrator must also allow Bridge's TCP and UDP traffic.

Use this option only for older Bridge versions without a Receive port setting. Upgrade before using the simple one-port Internet setup.

Optimise graphics card for Bridge

NVIDIA graphics cards save power by slowing down between video frames. For Bridge this roughly doubles H.264 encoding and decoding time. This setting gives Bridge maximum performance in the NVIDIA driver. It applies to Bridge only, not to other programs.

Checking graphics card…

Run once on each Bridge computer, then restart Bridge. Manual alternative: NVIDIA Control Panel → Manage 3D settings → Program settings → add C:\FastVideoBridge\.runtime\python.exe → Power management mode: Prefer maximum performance. Intel or AMD graphics need no change here.

If it does not connect

No source / connector in use

Check the selected source and SDI connector. Close another capture program using that connector, such as Media Express.

Timeout / check address

Start the receiver. Check its IP, URL port and TCP firewall rule. Over the Internet, also check router forwarding.

Connected, but no picture or sound

Check the source signal and the receiver's UDP rule and forwarding. TCP alone can connect without delivering video.

Wrong key / already connected

Use the same key on both sides. Stop the previous sender before starting another one.

Local outputs, control page and Internet protection

OMT and NDI stay on the local network and need the application's LAN firewall permissions. SDI needs Blackmagic Desktop Video and a free connector. These outputs do not require additional router forwarding.

The control page uses local TCP port 18879. Keep it local; do not forward it in the router. Internal encoder ports also stay local.

For ongoing Internet use, protect WHIP's connection URL with HTTPS. WebRTC video and audio are encrypted. A receiver behind CGNAT or without a reachable public IPv4 needs an alternative route, such as a relay.
