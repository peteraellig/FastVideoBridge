FastVideo Bridge 0.0.2.14 - 2026-10-08
Adaptive hardware decoding: D3D11VA, named Intel Quick Sync decoder with async_depth=1, then CUDA where supported, then explicit software fallback. Hardware API and active codec configuration are verified, and the UI reports hardware only after actual frames are decoded.
Added H265 receive negotiation and RFC 7798 single NAL, fragmentation and aggregation depayloading (single layer, no DONL).
GPU copy-back NV12 surfaces are passed directly to native OMT without UYVY colour conversion. Padded rows and non-adjacent planes are handled with stride-preserving packing. Software / other pixel formats retain the single-thread UYVY fallback.
Five tests passed: missing-hardware software decode; HEVC FU roundtrip; all three WHIP codecs and reconnect into OMT with stereo 48 kHz audio and decoded picture-content validation; diagnostics authentication; source cadence despite queue skips.
Actual local GPU test: H264 D3D11VA hardware true; H265 D3D11VA hardware true; AV1 QSV hardware true. AV1 D3D11VA fails on this machine, so the alternative Intel hardware path is used.
Isolated test GUI confirmed Decoder: Hardware D3D11VA, about 2.1 ms p95 and OMT output about 1.1 ms p95 at 320x180p25. These test figures do not predict 720p50 performance on .102.
Receiver .102 baseline before new hardware build: 720p50, zero video/audio queue drops, OMT output average 11.2 ms / p95 13.5 ms; user end-to-end picture comparison about 260 ms.
Receiver .102 requires its Update-Bridge helper or Setup 0.0.2.14 before actual GPU performance can be measured there.
Original FastVideo is not modified. Isolated test service stopped after verification.
