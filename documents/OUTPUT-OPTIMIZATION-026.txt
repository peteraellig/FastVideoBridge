FastVideo Bridge 0.0.2.26 - output pipeline

NDI: asynchronous SDK video submission, retained PyAV image buffers until
the next synchronizing call, explicit flush before destroy. Video and audio
use independent locks. Sender clocks remain derived from received RTCP.
OMT: reuse the NV12 packing buffer when decoded planes are not adjacent.
Native send remains synchronous, so packing storage is safe to reuse.
Both: dedicated single-worker executors per media type, one outstanding
submission per consumer, drain running native work before reconnect/destroy.
Diagnostics separate worker dispatch, processing and event-loop resume.

Warnings wrap within the card. Normal diagnostics use neutral text; warnings
stay orange with the measured p95 and frame budget. Recovery retains the
existing six-second hysteresis and is tested without reconnecting.

Local 1080p50 stereo output comparison, 350 video/audio submissions per trial:
NDI output p95 6.04 -> 4.22 ms (one initial video frame missed by discovery tap
in both trials); OMT 3.22 -> 2.92 ms; 350 audio frames received in each trial.
Short live OMT -> H264 WHIP -> output tests on .104, 27 seconds per output,
18 seconds measured after warm-up: NDI 50.02 fps, OMT 49.94 fps, no additional
video/audio receiver queue drops. Last output p95 NDI 10.95 ms / OMT 2.67 ms.
These are short local checks, not an hour-long endurance or end-to-end latency
measurement. Native output comparison and codec/reconnect tests exercised
real NDI/OMT taps; live UI test measures accepted receiver output submissions.
Hardware receive tests passed for H264, H265 and AV1, both output types.
