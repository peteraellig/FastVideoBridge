FastVideo Bridge 0.0.2.32 - input optimization

A common QueryPerformanceCounter media clock replaces the coarse Windows
Python 3.12 monotonic clock for capture, source timeline, audio deadlines and
input preview age. Transport/RTCP clocks and source timestamps are unchanged.
Colour conversion remains once per source frame on the serial bounded worker;
native swscale uses at most four threads, bounded to half the logical CPUs.
Encoder pixels remain private; live 1080p images were identical at 1/2/4 threads.

Local .104 measurements, 1920x1080p50:
Before -> after (same input/consumer test):
Colour conversion mean: 3.646 -> 1.275 ms.
Release lateness mean: 8.521 -> 0.894 ms; p95: 14.987 -> 1.988 ms.
With H264 QSV encoding: OMT 49.998 fps, local Full NDI 50.006 fps.
Stable 12-second windows: no additional source-frame gaps, deadline drops,
audio discontinuities, audio buffer drops or missing audio samples.
Hardware initialization did cause startup gaps; these are recorded separately.
NDI test source was generated locally; no external NDI-HX device was available.
These timings are local processing measurements, not whole-chain latency.

36 relevant tests passed, including independent-clock epoch checks, common
A/V deadline consistency, preview freshness and per-encoder pixel ownership.
Four actual installed-server source starts passed with video/audio signal,
50 fps and no automatic recovery. Installer independently installed and checked:
2033 payload files, zero missing/mismatched files; server and gateway HTTP 200.
