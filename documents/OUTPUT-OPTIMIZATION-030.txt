FastVideo Bridge 0.0.2.30 - native output comparison, 10 October 2026

OMT, measured locally on .104 with a native connected OMT receiver:
12 captured 1920x1080 NV12 pictures, 50 fps, 200 pictures per run;
two rounds, SDK/direct order reversed. Output quality unchanged (OMT HQ).

                       Mean call ms      p95 call ms
Standard OMT SDK       2.477 / 2.449      3.104 / 3.018
Direct VMX, 4 threads  1.417 / 1.340      1.827 / 1.641

Every run delivered 200 pictures and 109123957 compressed bytes. Separate
tests confirmed exact encoded byte equality when changing VMX worker count,
native OMT decoding, colours, timestamps, size changes and SDK fallback.
The direct path avoids packing two GPU download planes into a large NV12
buffer. It uses the public bundled VMX API and existing OMT network sender.
These are output-call times, not total WHIP/monitor-to-monitor latency, and
do not establish the improvement on .102 or on different CPUs/content.
